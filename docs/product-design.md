- 状态：三窗口 UI + M1–M4 基础已实现；实现状态见 [status.md](status.md)

## 1. 一句话

**像 Minecraft 启动器一样管理 MOSS-Image**：装得快、版本分得清、权重不迷路、跑起来看得懂、
出错能修、更新不用盯 GitHub。

## 2. 定位与非目标

**V1 是“运行时编排器 + 安装/资产管理器”，不是推理引擎。**

它负责：环境体检、实例（版本）管理、Python 运行时、权重/适配器管理、进程生命周期、
日志翻译、错误诊断、WebUI、更新与公告。

它不负责：模型图、kernel、量化推理、采样器实现、训练（训练走外部桥接，见 ADR-0002）。

**目标用户**

| 用户 | 场景 | 关键诉求 |
| --- | --- | --- |
| A. Mac 设计师/爱好者 | 看到 MOSS 的图，想在自己电脑试 | 不用碰终端；知道能不能跑、要等多久 |
| B. Windows/Linux 玩家 | 多套配置、多个 LoRA | 实例隔离、模组式管理、下载队列 |
| C. 研究者/小团队 | 复现某个 commit 的结果 | 精确版本、可导出、日志可追溯 |
| D. 移动端（V2+） | 手机出图 | 后续 |

**非目标（V1）**

- 自研推理后端（ADR-0003）；
- 训练/微调 UI（V2 走外部训练器桥接）；
- img2img / edit（官方未发布）；
- 云端账号、模型市场后端、遥测。

## 3. 设计原则

1. **默认安全**：不执行模型包里的代码；不静默安装；更新必须验签。
2. **可解释**：每个自动决策（换源、降档、复用运行时）都在 UI 里说明理由。
3. **可回滚**：实例固定 commit；运行时/模型/适配器都可单独修复或删除。
4. **不打断**：错误先落“诊断”，只有需要用户决策时才弹窗；绝不弹窗循环。
5. **小窗优先**：默认 1180×760，信息密度高但不拥挤；可最大化，不做全屏启动。
6. **离线可用**：已有实例、已下载模型、已缓存公告在断网时仍可查看与启动。

## 4. 术语

| 术语 | 含义 |
| --- | --- |
| **实例 Instance** | 绑定到某个 git commit 的可运行副本：代码快照 + 运行时引用 + 模型/适配器选择 + 启动参数 |
| **运行时 Runtime** | Python 解释器 + 依赖集合；默认按“Python 版本 + 依赖锁 + 平台/加速器”共享 |
| **模型包 Model Pack** | 一组权重（DiT/TE/VAE），官方或第三方/量化；按内容哈希存储 |
| **适配器 Adapter** | LoRA / LyCORIS / DMD 等增量文件 |
| **来源 Source** | GitHub 仓库 + 分支；默认 `OpenMOSS/MOSS-Image` |
| **稳定版 Stable** | `main` HEAD，或 `release/manifest.json` 里 `recommended_commit` 指定的提交 |
| **启动配置 Profile** | 分辨率、步数档、精度、offload、端口等 |
| **诊断 Diagnostic** | 解析出的错误卡片：原因 + 解决方案 + 原始日志 |
| **公告 Announcement** | `release/` 里的 markdown，显示在首页与公告页 |

窗口：启动器 **1180×760**（最小 960×640），创作 **1320×860**，终端 **1120×720**；
macOS `hiddenInset` + `vibrancy: under-window`，Windows `titleBarOverlay` + acrylic。
标题栏居中 `CloverMoss` + `dev`/`release` + 版本号。

### 5.1 UI v0.3 当前布局（2026-10-19）

- **视觉**：中性深灰亚克力，无深蓝底、无蓝色渐变、无绿色；文字为冷调浅蓝白，
  蓝色只做激活/焦点/少量图标；只保留深色主题。
- **层级**：标题栏/侧栏薄亚克力，主内容区后亚克力，卡片更薄；发丝边代替重阴影。
- **标题栏**：全宽 44 px；不再有侧栏 Logo/品牌块；左侧折叠/返回，右侧创作、终端、通知。
- **侧栏**：启动器 200 px ↔ 56 px；只有首页/实例/模型/诊断/设置；无版本块。
- **首页**：欢迎语 + 固定宽度居中的底部启动条 + 运行栈；主区域有 16:9 背景图（设置可换）。启动条为
  `Case / 后端 / 实例 / 设备 / 档位 / 高级 / 启动`；
  启动条固定在底部、低高度宽幅；运行后锁定为停止/终端；新的空白启动条永远置顶，运行中的 Case 收在下方，可折叠/排序。
- **通知**：右上角单个大矩形，默认展开；用标题、段落、发丝线分区，不再卡片套卡片。
- **OOBE**：启动器内全屏遮罩，单页三行；没有可启动实例时默认出现，可本次跳过。
- **创作**：独立窗口承接 Studio/画廊；Clover 常驻后端下一轮接入。
- **终端**：独立窗口；左侧 Case 列表，右侧 xterm.js；支持停止、stdin。

```
┌──────────────────────────────────────────────────────────────────┐
│ 生成  实例 moss-main-c1355e6 · 768×768 · 8 步 · seed 42          │
│ Prompt ┌──────────────────────────────────────────────────────┐  │
│        │ a rainy night watch repair shop, ...                 │  │
│        └──────────────────────────────────────────────────────┘  │
```

- 进度条按 stage 分段：`加载 → 文本编码 → 去噪（N/M）→ 解码 → 保存`；
- 识别多个并发进度条（下载 + 去噪）时，主进度取“去噪”，下载放侧栏；
- 控制台保留原始输出（ANSI 颜色），可搜索、复制、清空；
- stdin 输入框：进程等待输入时高亮（如 HF 登录、确认提示）；
- 停止：先 SIGINT，5 s 后强制结束，UI 显示“正在停止”。

```
诊断                                   [全部] [错误] [警告]  [导出诊断包]
┌──────────────────────────────────────────────────────────────────┐
│ ✕ 显存不足（OOM）              2 分钟前 · moss-main-c1355e6      │
│   解码阶段内存耗尽（峰值 15.2 GB / 16 GB）。                      │
│   可能原因：1024² + bf16 + 未分块解码                             │
│   [降到 768² 重试] [启用分块解码] [查看文档]       原始日志 ▸      │
├──────────────────────────────────────────────────────────────────┤
│ ! Python 包缺失：xformers       5 分钟前 · 已自动忽略（1 小时）    │
└──────────────────────────────────────────────────────────────────┘
```

**弹窗策略（防无限循环）**

1. 错误一律进“诊断”列表；只有“需要用户决策”的错误才弹 toast；
2. 同一 `signature` 60 s 内只弹一次，5 min 内最多 3 条；
3. 进程 10 min 内崩溃 3 次 → 停止自动重启，只留卡片；
4. 每条规则可“静音 1 小时 / 永久忽略”；
5. 弹窗永不阻塞主流程，永不嵌套。

- **网络**：自动/直连/镜像；GitHub、PyPI、HF 分别可选；探测结果与手动覆盖；

- **运行时**：默认 Python、uv 路径、共享/独立默认值；

- **隐私**：诊断数据本地保存，默认不上传。

## 7. 关键流程

### 7.1 首次启动

1. 打开小窗，显示骨架屏；
2. 并行执行环境扫描（≤5 s）：系统、GPU、内存/磁盘、Python/git、网络探测；
3. 首页展示报告与推荐档位；若缺 Python，提供“一键安装托管 Python”；
4. 引导“新建实例”；
5. 安装完成后提示下载模型（可后台）。

### 7.2 创建实例

1. 读取本地 git 镜像的分支与最近提交（无镜像则先克隆，显示进度）；
2. 选择分支 + commit（默认稳定版）；
3. 选择运行时：共享（命中已有锁）/ 独立 / 新建 Python；
4. 选择模型与适配器（可跳过）；
5. 创建 worktree、准备运行时（pip/uv 安装，显示包级进度与镜像选择）、写入实例配置；
6. 自检：`python -c "import torch, diffusers, transformers"` + 版本断言；
7. 完成，进入详情。

### 7.3 启动与进度

1. 预检：实例完整、模型存在、端口空闲、磁盘足够；
2. 选择适配器（Runner 或 Gradio）；
3. Supervisor 启动进程，注入环境变量（HF_HOME、镜像、MPS fallback 等）；
4. 解析 NDJSON / tqdm / 日志 → 更新进度与阶段；
5. 完成：结果入画廊（PNG + 元数据），写任务日志；
6. 失败：解析错误 → 诊断卡片 +（必要时）toast；保留原始日志。

### 7.4 更新实例

1. `git fetch` 上游；
2. 对比当前 commit 与 `main`，列出中间提交；
3. 展示“更新说明”（提交标题 + diff 链接 + requirements 变化）；
4. 用户确认：移动 pin（可回滚）或“克隆为新实例”；
5. 若依赖变化，提示重建运行时（共享锁变化时自动新建）。

### 7.5 应用更新与公告

1. 启动时异步拉取 `release/manifest.json`（jsDelivr → raw → 代理 → 缓存）；
2. 校验 schema + 签名 + 版本/通道；
3. 有新版本：首页顶部条 + “检查更新”页；
4. 公告：首页卡片 + 公告页，按 id 记住已读/不再显示；
5. 下载更新：后台、可暂停、校验 sha256，重启后安装；
6. 离线：显示缓存公告与“上次检查时间”。

### 7.6 WebUI

两种入口，互不干扰：

- **启动器 Web 模式**：设置里开启，浏览器访问 `http://<host>:<port>/?token=…`，
  手机扫码即可看队列、画廊、日志；默认仅本机，局域网需显式开启；
- **Gradio**：实例以 Gradio 适配器启动后，应用内嵌或外部浏览器打开官方界面。

### 7.7 换源

- 启动时与网络变化时探测：GitHub（git/raw/api）、PyPI、HuggingFace；
- 评分：3 s 超时、延迟、失败率；选出每类服务的最佳端点；
- 应用到：`git -c url.<mirror>.insteadOf`、`PIP_INDEX_URL`/`PIP_EXTRA_INDEX_URL`、
  `HF_ENDPOINT`；
- UI 显示“当前：直连 GitHub / 清华 PyPI / hf-mirror”，可手动覆盖；
- 失败自动重试一次并降级，不静默改写用户配置。

## 8. 版本与“稳定版”语义

MOSS-Image 目前**只有 `main` 分支、没有 tag**。因此：

| 标记 | 条件 | 说明 |
| --- | --- | --- |
| **稳定版** | commit == `main` HEAD，或 == `release/manifest.json` 的 `recommended_commit` | 我们主动标记；推荐提交可随 manifest 更新，不用发版 |
| **旧版** | 落后 `main` HEAD | 显示落后提交数与“更新” |
| **实验** | 其它分支 / 非 HEAD 提交 | 允许安装，标黄 |
| **自定义** | 用户填入的 fork/commit | 风险提示 |

- 实例永远固定到完整 SHA；短 hash 只用于展示；
- 更新 = 移动 pin，旧 commit 仍在本地 git 对象里，可秒级回滚；
- 导出的实例包（`.cloverpack`）含 pin 的 SHA，不含权重。

## 10. 错误与文案

- 文案原则：**发生了什么 → 为什么 → 你可以做什么**，每张卡片最多 3 个动作；
- 不出现裸 traceback（折叠在“原始日志”里）；
- 不出现“未知错误”，至少归类为“程序异常退出”，附 exit code 与最后 20 行；
- 错误码稳定（`E_OOM`、`E_DISK`、`E_NET`…），便于社区检索；
- 所有“修复”动作必须可撤销或可重试。

**首批错误规则**：OOM（CUDA/MPS/统一内存）、缺包、版本冲突、网络/SSL、磁盘满、
权限、端口占用、HF 鉴权/限流、模型文件损坏、MPS 不支持算子、进程被系统杀死。
